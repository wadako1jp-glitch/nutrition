# 公開までの道筋

## Phase 0: 要件・画面確定（完了）
- 用紙準拠のワークシート型UI、即時計算、あいまい検索＋番号直打ち、丸め/可食部/献立小計のルール確定
- モック作成済み

## Phase 1: データ基盤
- 【新規】調理による重量変化率表（八訂付録）の取り込み。米の炊飯、乾物の戻し、おろし物の歩留まり等、使用量と栄養計算重量が異なる食品に対応
- 学校給食献立情報は有料機能（学校給食基準の献立参照）専用データに位置づけ直し。無料の「一般的なレシピ」は別ソースを探す（農林水産省「うちの郷土料理」が郷土料理テーマの候補）
- 八訂 本表Excel（2020年版 or 増補2023 — 学校に合わせる）→ JSON 変換スクリプト（`scripts/`）
  - 「Tr」「(0)」「-」等の表記を数値/欠損に正規化、廃棄率も取り込む
  - 出力は `data/mext-tables/<版>/foods.json`（版ごとにディレクトリ）
- 食材検索の表記ゆれ対応（検証済み・軽量な2層構成に変更）
  1. ルール正規化（辞書不要）: かな統一、全角/半角、長音・小書き、空白除去 → かな正規化した上で前方一致＋bigram部分一致
  2. 固定変換リスト（実証済み）: 濃口醤油→こいくちしょうゆ、牛→うし、鶏→にわとり 等、20〜30語程度。用紙4枚・約84語の検証で、部分一致86%→この層を足すとほぼ100%ヒットを確認済み（`data/synonyms/common-terms.py`にseed済み）
  - AI大量生成（3層目）は当初想定より優先度低。上記でカバーできない実例が出たら追加検討
  - 育成: ヒットしなかった入力と最終的に選ばれた食品を端末内ログ→エクスポートし、辞書に取り込む
- 記入済み用紙サンプル（`data/samples/`）をテストケース化し、計算結果を答え合わせ

- 学校給食レシピの取り込み: 自治体標準オープンデータセット「学校給食献立情報」（豊中市CSV等、食品番号＋分量入り）→ アプリのレシピJSONへ変換（詳細は docs/data-sources.md）

## Phase 2: コア実装（React + Vite、Webアプリ/PWA）
【方針転換】まずはネイティブ(Expo)ではなくスマホ向けWebアプリで様子見。データのほとんどをDBで持たない構成のため身軽に検証できる（詳細はCLAUDE.md「技術スタック」参照）
- Viteプロジェクト立ち上げ、用紙UI（左固定＋横スクロール）。既存の`.dc.html`モックをベースに実装
- 食材検索（あいまい・番号）→ 重量入力 → 行の即時計算 → 献立小計
- 献立の保存・編集（ブラウザstorage、JSON。`src/lib/storage/`経由）
- レシピのインポート/エクスポート（JSONファイルのダウンロード／Web Share API）
- 塩分濃度表示（料理区分ごと）
- **PWA化**: manifest.json、アイコン、service workerで①ホーム画面に追加できる②静的データ（成分表JSON等）とアプリ本体をキャッシュしオフラインで起動・計算できる、の2点を満たす
- ホスティング: Vercel / Cloudflare Pages / Netlify 等の無料枠でOK（独自ドメインは任意）

## Phase 5（将来・保留）: ネイティブアプリ化の再検討
Web版で使われる実績・フィードバックが溜まった段階で、必要なら以下を検討する（今回のスコープからは一旦外す。破棄ではなく先送り）
- React Native + Expo でネイティブ化（`src/core/`等ロジック層はほぼ流用可能、`src/lib/storage/`の実装だけ差し替え）
- Apple Developer Program 登録（年$99）、Google Play デベロッパー登録（$25、個人アカウントは公開前に20人×14日間のクローズドテストが必須）
- 課金モデル（基本無料＋300円買い切り）は、Web版でも `Stripe` 等の決済を使えば実装できる。ネイティブ化を待たずにWeb版のまま試すことも選択肢
